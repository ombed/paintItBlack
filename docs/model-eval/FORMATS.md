# Model evaluation: shared formats and places

Every part of the harness (`bench/model-eval/`) reads and writes these shapes. The plan is
`docs/model-eval/PLAN.md`. JSON files are UTF-8, pretty-printed with one-space indent.

## Gold set

```json
{ "name": "synthetic-tune", "source": "bench/key.json", "licence": "repo", "split": "tune",
  "docs": [ { "id": "m1", "genre": "meeting", "text": "…the document text…",
    "mentions": [ { "s": 12, "e": 21, "type": "PER", "must": true, "cat": "P_ARABIC", "ent": "m1#3" } ] } ] }
```

- `text` for our documents is exactly what the product hands the model: the blocks of
  `E.readBlocks(buf)`, their `.text` joined with `"\n"` (see `nerRun` in `engine/08-docx.js`).
- `type` is one of `PER`, `ORG`, `PLACE`. `PLACE` merges GPE, LOC and FAC. Other types are dropped.
- `must` (our sets only): true for an entity that must be redacted; false for a trap or a public
  body (a negative: proposing it is a false positive).
- `cat`, `ent` (our sets only): the key's category and a stable id per entity (all mentions of
  one person share an `ent`).
- Offsets are JavaScript string indices (UTF-16 code units) into `text`, `e` exclusive.
- Public sets carry `"licence"` and `"contamination": ["model keys trained on it"]`.

## Model registry entry (`registry.json`, an array)

```json
{ "key": "base-q8", "repo": "onnx-community/dictabert-ner-ONNX", "revision": "4f0aabf58566526df6f3fb548e0fd2619fbf2b1d",
  "dtype": "q8", "file": "onnx/model_quantized.onnx", "sha256": "…64 hex…", "bytes": 184984466,
  "source": "hub", "localPath": null,
  "labelScheme": "BIO", "labelMap": { "PER": "PER", "ORG": "ORG", "GPE": "PLACE", "LOC": "PLACE", "FAC": "PLACE" },
  "tokenizer": "wordpiece", "licence": "CC-BY-4.0", "shippable": true, "tier": 1,
  "trainedOn": ["unknown"], "notes": "" }
```

- `source`: `hub` (downloaded from the pinned revision) or `local` (an export under `model-cache/<key>/`,
  laid out as transformers.js expects: `config.json`, tokenizer files, `onnx/model*.onnx`).
- `labelScheme`: `BIO`, `BIOES`, `IO`, `B_only`, `IOB1`. `labelMap` maps the model's type names
  (without the prefix) to `PER`/`ORG`/`PLACE`, or `null` to drop. An unmapped name is a harness error.
- Loading refuses a file whose sha256 differs from the registry.

## Predictions

```json
{ "model": "base-q8", "set": "synthetic-test", "stage": "raw", "threshold": 0,
  "docs": [ { "id": "m1", "spans": [ { "s": 12, "e": 21, "type": "PER", "score": 0.97 } ] } ],
  "health": { "unmappedLabels": 0, "chunksOver510": 0, "chunkErrors": 0,
    "alignFailTokens": 0, "alignFailEntityTokens": 0, "entityTokens": 0, "tokens": 0 },
  "timing": { "loadMs": 0, "scanMs": 0, "words": 0 } }
```

- `raw`: after the adapter, `E.nerAlign` and `E.nerGroup`, before `E.nerClean`; every span kept with its
  score (threshold 0), so the cut-off sweep is done offline from this file.
- `cleaned`: `E.nerClean` returns names, not positions. Its output is scored per name: every
  occurrence of a cleaned value in `text` that the product would replace, bare or after a prefix letter
  (`E.variants(v, "normal")`, each form matched with `E.NW + E.flex(form) + E.NWE`), is a predicted span
  with the cleaned kind; the span leaves the prefix letter out, as the gold does.
- `health.alignFailEntityTokens` counts tokens inside a gold mention that `nerAlign` could not place, out of
  `health.entityTokens` tokens inside gold mentions.
- Where two chunks overlap (60 characters), one span can come back twice in `raw`, as it does in the product;
  the scorer counts a span once per (document, start, end, type).

## Scores (`score-spans.js` output)

```json
{ "model": "base-q8", "set": "protocol", "stage": "raw", "threshold": 0.6, "match": "overlap-untyped",
  "micro": { "tp": 0, "fp": 0, "fn": 0, "p": 0, "r": 0, "f1": 0, "f2": 0 },
  "perType": { "PER": { "…": 0 } }, "ci95": { "r": [0, 0], "f2": [0, 0] } }
```

`match` is one of `word-exact`, `overlap-typed`, `overlap-untyped`, as defined in PLAN.md 3.1.

## Private gold sets

A gold set built from her documents has `"licence": "private"` and lives under `private-bench/model-eval/`;
`compare.js` switches to counts-only output on either.

## Privacy rule for code that touches private sets

Anything written outside `private-bench/` or printed to the console during a private run goes
through `bench/model-eval/privacy.js`, which lets through only numbers, fixed label names,
category ids and fixture folder names, and refuses everything else.
